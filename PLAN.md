# Claude Cage — пошаговый план для Codex

## Правило работы

Идти строго по этапам. Не переходить к следующему этапу, пока не выполнены проверки текущего. Перед потенциально опасными изменениями Windows, сети или виртуализации объяснить пользователю действие и запросить подтверждение.

Не помещать в Git:
- proxy username/password;
- токены Claude/Anthropic;
- cookies/session data;
- приватные ключи;
- содержимое локальных credential/config файлов.

## Этап 0. Подготовить репозиторий

1. Клонировать `konicaRu/claude_cage` в:
   `C:\claude_code_projects\claude_cage`.
2. Прочитать `project-starter.md`.
3. Создать/актуализировать:
   - `README.md`;
   - `MEMORY.md`;
   - `ARCHITECTURE.md`;
   - `.gitignore`.
4. В README сослаться на `GOAL.md` и этот `PLAN.md`.
5. Проверить `git status`.
6. Сделать стартовый commit.

**Gate 0:** репозиторий чистый, секретов нет, цель проекта зафиксирована.

## Этап 1. Аудит Windows 10

Codex только собирает факты, ничего не включает автоматически.

Проверить:
- точную версию/редакцию Windows 10;
- x64;
- CPU и аппаратную виртуализацию;
- включена ли Virtual Machine Platform;
- состояние Hyper-V/Windows hypervisor;
- свободное место на диске;
- RAM;
- конфликты с VMware/VirtualBox/WSL при наличии;
- установлен ли уже Claude Desktop/Cage.

Результат записать в `docs/environment-audit.md`.

**Gate 1:** подтверждено, что хост соответствует требованиям выбранного Linux guest.

## Этап 2. Установить Claude Cage

1. Использовать официальный релиз Claude Cage.
2. Проверить checksum/источник установщика, если проект публикует checksum.
3. Установить Cage.
4. Создать Linux guest, совместимый с Cage и официальным Claude Desktop.
5. На Windows 10 предпочесть поддерживаемый Linux guest, а не пытаться создавать неподдерживаемый Windows 11 guest.
6. Проверить запуск терминала и браузера внутри Cage.

Результат: `docs/cage-install.md`.

**Gate 2:** Linux guest запускается повторно без ошибок.

## Этап 3. Получить и проверить dedicated ISP proxy

Требования:
- один статический dedicated IP;
- SOCKS5;
- выбранная стабильная география;
- хорошая репутация;
- без ротации.

До авторизации Claude проверить IP через несколько независимых reputation/IP-сервисов.

Записать в `docs/proxy-validation.md`:
- провайдера;
- страну;
- ASN/ISP;
- дату проверки;
- итог репутационных проверок;
- внешний IP можно маскировать, например `185.xxx.xxx.42`.

НИКОГДА не записывать username/password прокси.

**Gate 3:** IP признан пригодным пользователем.

## Этап 4. Настроить прокси в Cage

1. Добавить SOCKS5 node средствами Cage/Mihomo.
2. Секреты вводить локально.
3. Применить узел.
4. Проверить внешний IP из guest.
5. Проверить DNS.
6. Проверить поведение при отключении proxy:
   - внешний трафик Claude-среды не должен незаметно переключаться на прямой маршрут.
7. После восстановления proxy повторить проверку.

Результат: `docs/network-validation.md`.

**Gate 4:** ожидаемый IP стабилен, fail-closed поведение подтверждено.

## Этап 5. Установить Claude Desktop в Linux guest

1. Использовать официальный способ установки Anthropic для Ubuntu/Debian.
2. Не использовать неофициальные repack-сборки.
3. Запустить Claude Desktop.
4. До входа ещё раз проверить внешний IP среды.
5. Выполнить штатную авторизацию пользователя.
6. Отправить тестовое сообщение.
7. Перезапустить приложение и проверить сохранение сессии.

Результат: `docs/claude-desktop.md`.

**Gate 5:** официальный Claude Desktop работает через выбранный сетевой контур.

## Этап 6. Claude Code

1. Проверить, доступен ли Claude Code через установленный Claude Desktop.
2. При необходимости установить официальный Claude Code в Linux guest.
3. Проверить `claude --version`.
4. Создать небольшой тестовый Git-проект.
5. Запустить Claude Code.
6. Проверить чтение файла, безопасное изменение и Git diff.
7. Проверить внешний IP во время работы.

Результат: `docs/claude-code.md`.

**Gate 6:** Claude Code выполняет тестовую задачу и Git diff корректен.

## Этап 7. Общая проверка маршрута

Последовательно проверить из:
- браузера Cage;
- Claude Desktop;
- терминала/Claude Code.

Ожидаемый результат: все сетевые клиенты Cage используют один настроенный egress.

Не пытаться обходить защитные механизмы сервиса. Если сервис отклоняет соединение или аккаунт, зафиксировать ошибку и остановиться для диагностики.

**Gate 7:** сетевой контур воспроизводим.

## Этап 8. Перезагрузка и persistence test

1. Сохранить работу.
2. Перезагрузить Windows.
3. Запустить Cage.
4. Запустить Linux guest.
5. Проверить proxy.
6. Проверить IP.
7. Запустить Claude Desktop.
8. Запустить Claude Code.
9. Убедиться, что Browsec/системный VPN Windows выключен.

Результат: `docs/persistence-test.md`.

**Gate 8:** весь сценарий работает после cold start.

## Этап 9. Документация

Обновить:
- `README.md` — инструкция пользователя;
- `ARCHITECTURE.md` — фактическая архитектура;
- `MEMORY.md` — что сделано и открытые вопросы;
- `docs/troubleshooting.md` — типовые сбои;
- `docs/security.md` — где хранятся секреты и что запрещено коммитить.

## Этап 10. Финальный acceptance test

Проверить чек-лист из `GOAL.md`.

Финальный результат должен позволять пользователю:
1. включить ПК;
2. запустить Cage;
3. запустить Claude Desktop;
4. запустить Claude Code;
5. работать без системного VPN Windows;
6. использовать один настроенный статический egress IP;
7. не вводить proxy credentials заново при каждом штатном запуске, если Cage поддерживает безопасное локальное хранение.

Если какой-либо пункт не подтвержден реальным тестом, не помечать проект как готовый.

## Отдельные ограничения

На текущем целевом Linux guest:
- обычный Claude Desktop является целью проекта;
- Claude Code является целью проекта;
- Computer Use не считать обязательным критерием;
- Cowork не считать обязательным критерием, особенно при отсутствии поддерживаемой nested virtualization.

## Принцип диагностики

При проблеме:
1. воспроизвести;
2. собрать конкретную ошибку/лог;
3. сформулировать гипотезу;
4. проверить её минимальным изменением;
5. не менять одновременно несколько сетевых/виртуализационных параметров;
6. после исправления повторить соответствующий Gate.
