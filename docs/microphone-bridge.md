# Микрофон Realtek в Cage

## Автоматическое подключение

Открывайте Cage обычным способом. Фоновый помощник ждёт готовности Linux и автоматически подключает Realtek как `Realtek_Bridge`. Окно управления и ручные CMD-команды не нужны; включайте и выключайте диктовку кнопкой в самом Claude.

Помощник установлен в пользовательскую автозагрузку Windows: `Cage Microphone.lnk`. Он не запускает Cage или VM самостоятельно. Проверка приложения и готовности среды выполняется раз в 5 секунд; после полного выхода из Cage или остановки Linux захват прекращается. Обычное закрытие окна Cage может скрывать его в трей — тогда Cage продолжает работать. При недоступном Realtek сначала выполняется проверка открытия устройства; повторные попытки идут с паузой 30 секунд, не перезапуская звук Linux при каждой попытке.

Если Claude не обнаружил Realtek_Bridge, закройте только Claude Desktop кнопкой **关闭应用** и откройте его снова. Пользователь подтвердил работу диктовки после такого перезапуска.

Пока Cage и мост работают, Realtek захватывает звук постоянно, независимо от кнопки диктовки Claude. Кнопка управляет использованием звука самим Claude. Запись на диск не сохраняется. Ограничение пробного запуска в 14 минут снято.

Программа использует установленный Python 3.11, FFmpeg и штатный `cage run`. Исходники — `scripts/microphone_bridge.py` и соседние shell/PowerShell-файлы; локальные журналы и `automatic.json` — `.local/microphone/`. Повторный экземпляр отклоняется. Для восстановления автозагрузки: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/install-microphone-auto.ps1`. Удаление `Cage Microphone.lnk` из пользовательской папки автозагрузки отменяет последующие автоматические запуски помощника. Путь к проекту не менять без обновления ярлыка.

Конфигурация гостя создаётся только в `/run/cage-mic-bridge/` и runtime override звуковой службы. При отключении восстанавливается штатный PulseAudio; конфигурации `/etc`, прокси и сетевые маршруты не изменяются. На Windows Job Object завершает захват при аварии управляющей программы. Linux получает heartbeat каждые 20 секунд; при отсутствии heartbeat более 90 секунд watchdog восстанавливает звук на очередной проверке (обычно в пределах 120 секунд). Ошибка восстановления оставляет watchdog для повторной попытки. Выключение гостя также удаляет runtime-конфигурацию.

Проверены 14 модульных тестов, включая ожидание Cage/Linux, единственный запуск, остановку, отмену и паузу повторных попыток. Ранее проверены реальная передача звука, stop/restart и watchdog. Подтверждено автоматическое обнаружение уже работающего Cage и подключение Realtek без ручного окна. Полный новый вход в Windows и реальный выход из Cage в этой проверке не выполнялись, чтобы не прерывать пользовательскую сессию.

## История временного прототипа — 2026-11-13

По согласованию с пользователем запущен экспериментальный мост Windows Realtek USB2.0 Audio → FFmpeg DirectShow → stdin штатной команды `cage run` → PulseAudio module-pipe-source `cage_realtek` (Realtek_Bridge). PCM s16le, mono, 48000 Hz. Новые сетевые слушатели не создавались.

После устранения накопления буфера при простое проверка Linux получила 288000 байт (3 секунды), peak 289, RMS 21.21. Дополнительный потребитель `parec` отбрасывает звук, пока Claude не использует источник, чтобы FIFO продолжал получать текущий сигнал. Повторная проверка не показала предупреждений о переполнении. Это подтверждает поступление ненулевого сигнала, но не качество речи и не работу диктовки Claude. Последнее проверяет пользователь.

Прототип и журналы находятся в исключённой из Git `.local/`: `mic-bridge.py`, `check-mic-bridge.py`, `mic-bridge.log`. Аудиозапись проверки не сохранялась. Захват включён на всё время работы моста, даже когда кнопка диктовки Claude выключена.

В guest созданы только временные файлы `/run/cage-mic-bridge/` и `/run/systemd/system/cage-audio.service.d/90-mic-bridge.conf`. Исходные конфигурации `/etc` не изменены. Аудиослужба перезапущена с дополнительным виртуальным источником; запрет динамической загрузки модулей сохранён. Автозагрузка Windows не настроена.

Остановка: создать `.local/mic-bridge.stop` в корне проекта. Контроллер прекращает захват, удаляет собственный runtime override и перезапускает исходную аудиослужбу. Контроллер ограничен 14 минутами; независимый systemd timer `cage-mic-bridge-rollback.timer` запускает откат через 15 минут. Остановка VM также удаляет `/run`-настройку.

Первый запуск прервался из-за кодировки журнала Windows. После него подтверждено восстановление исходного источника `cage_output.monitor` и отсутствие runtime override. Кодировка исправлена; повторный запуск передаёт звук. Не считать эксперимент постоянной установкой.

Источники: [аудиоконфигурация Cage v0.1.7](https://github.com/Lee-xeo/Claude-Cage/blob/v0.1.7/internal/cage/guest-audio.sh), [FFmpeg DirectShow](https://ffmpeg.org/ffmpeg-devices.html#dshow).
