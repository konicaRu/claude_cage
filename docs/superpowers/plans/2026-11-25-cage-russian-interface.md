# Проверка русского интерфейса и обновления Cage

**Цель** — проверить русский интерфейс Cage 0.2.1 и выяснить, переносится ли рабочая среда из 0.1.7.

**Статус** — план. Испытания проводятся в отдельной Windows-среде. Рабочую установку 0.1.7 можно обновлять только по отдельному решению пользователя после испытаний.

В исходниках 0.1.7 нет переключателя языка интерфейса. В более новых исходниках есть русский каталог. Наличие переключателя в готовой Windows-сборке 0.2.1 предстоит проверить. Разработчики описали успешное обновление 0.2.0 → 0.2.1 на Windows. Переход 0.1.7 → 0.2.1 остаётся предметом испытания. [Релиз Cage 0.2.1](https://github.com/Lee-xeo/Claude-Cage/releases/tag/v0.2.1)

## 1. Проверить русский в чистой установке

- [ ] Подготовить отдельную Windows-среду со снимками. Для проверки запуска гостевой VM нужен доступ к аппаратной виртуализации. Проверить это до испытания, если тестовая Windows сама работает в VM.
- [ ] Скачать официальный Windows-установщик 0.2.1 и сверить SHA-256 с опубликованной суммой. Установить его в тестовой среде с пустым профилем.
- [ ] Открыть **Настройки → Общие → Язык интерфейса → Русский**. Проверить, сохраняется ли выбор после повторного открытия Cage.
- [ ] Проверить рабочую область, меню проектов, создание терминала, браузер, загрузки, настройки, окно сетевой проверки и меню в трее. Записать оставшиеся китайские подписи и ошибки отображения. Интерфейс Claude Desktop оценивать отдельно.
- [ ] Если русского в сборке нет или перевод основных действий непригоден, завершить испытание и записать результат.

**Что делаем за компьютером.** Открываем отдельную тестовую Windows с возможностью восстановления снимка. Скачиваем `Cage-0.2.1-windows-amd64-setup.exe` из официального релиза, сверяем SHA-256 через `Get-FileHash`, запускаем установщик внутри тестовой Windows. В Cage открываем **Настройки → Общие**, ищем **界面语言**, выбираем **Русский**. Проверяем, что пункты рабочего стола и меню читаются, затем закрываем и снова открываем тестовый Cage. Сохраняем скриншоты и список экранов, где остались китайские надписи. Если отдельной Windows пока нет, это первый блокер для запуска испытания.

## 2. Проверить обновление с 0.1.7

- [ ] В той же изолированной Windows-среде вернуться к чистому снимку и установить 0.1.7. Создать тестовый профиль, добавить отдельную папку проекта и записать контрольные файлы в гостевой диск и папку проекта. Использовать тестовый прокси, если он нужен для сетевых проверок.
- [ ] Зафиксировать исходное состояние. VM запускается, терминал открывается, контрольные файлы читаются, а сетевые проверки проходят при подключённом тестовом прокси.
- [ ] Штатно остановить тестовую среду и сделать снимок Windows вместе с профилем Cage, виртуальным диском и тестовым проектом. Сохранить установщик 0.1.7 для восстановления.
- [ ] Выполнить штатное обновление тестовой 0.1.7 до 0.2.1. Записать фактический маршрут и версии. Если прямой переход не поддерживается, отдельно испытать предложенный разработчиками или установщиком маршрут с промежуточной версией.
- [ ] Запустить Cage и проверить, что он подхватил прежний диск и проект. Открыть терминал, прочитать оба контрольных файла и проверить двустороннюю синхронизацию. Повторить сетевую проверку, открыть браузер и проверить подключение Claude Desktop и Claude Code, если доступны тестовые учётные данные. Пункты без тестового доступа отметить как непроверенные.
- [ ] Восстановить снимок с 0.1.7 и повторно открыть проект, терминал и оба контрольных файла. Это проверит процедуру отката на тестовой среде.

**Что делаем за компьютером.** После проверки перевода возвращаем тестовую Windows к снимку до установки Cage. Ставим 0.1.7 и добавляем в Cage пустую тестовую папку, например `C:\CageUpgradeTest`. В Windows создаём в ней `host-check.txt`, из терминала Cage читаем файл и создаём рядом `guest-check.txt`. В домашней папке Linux создаём отдельный `~/upgrade-check.txt` для проверки виртуального диска. Останавливаем тестовую VM, делаем снимок, затем запускаем обновление в тестовой Windows. После обновления проверяем все три файла и записываем новый файл из гостя в тестовую папку, чтобы проверить запись после миграции. Для проверки отката возвращаем снимок и снова читаем три исходных файла.

## 3. Принять решение о рабочей установке

- [ ] Из результатов испытания выписать подтверждённый маршрут обновления, качество перевода, сбои и непроверенные пункты. Тестовый профиль проверяет перенос на контрольных данных. Сохранность существующих авторизаций и настроек рабочего профиля потребует отдельной проверки.
- [ ] Если пользователь решит обновлять рабочий Cage, перед установкой штатно остановить VM и согласовать способ резервного копирования профиля, каталога данных `.local/CageData` и подключённых проектов. Проверить, что копия пригодна для восстановления и хранится вне каталогов, затрагиваемых обновлением.

**Оценка** — 30–60 минут на русский интерфейс при готовой тестовой Windows и ещё 1–3 часа на пробное обновление и откат. Подготовка тестовой Windows и устранение проблем с виртуализацией оцениваются отдельно.
