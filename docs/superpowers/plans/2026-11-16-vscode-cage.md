# Claude Code в привычном VS Code через Cage — план настройки

> Исполнение: последовательно в текущей сессии по навыку executing-plans. Этот документ фиксирует цель, способ и проверки. Невыполненные пункты отмечены `[ ]`.

**Цель:** пользователь общается с Claude Code в той же графической панели VS Code, что и раньше, а Claude Code выполняет работу внутри Cage и использует настроенный прокси IPRoyal.

**Как это устроено:** окно редактора остаётся в Windows. Через Remote SSH оно подключается к Linux Cage; расширение Claude Code и инструменты проекта запускаются в Linux. Локальные окна VS Code продолжают работать самостоятельно.

**Инструменты:** установленный VS Code, Microsoft Remote SSH, официальное расширение Anthropic Claude Code, штатный SSH-доступ Cage.

**Основание:** согласованный в беседе вариант — графическое расширение Claude Code, а не общение в терминале. Настройку выполняет агент; пользователь подключается для личной авторизации при необходимости.

## Что уже проверено

- Cage 0.1.7 и Linux запущены на момент проверки.
- В Linux установлен Claude Code 2.1.322, SSH разрешает нужные туннели.
- В Windows установлен VS Code 1.146.0, расширение Claude Code 2.1.325.
- Remote SSH среди установленных локальных расширений не найден.
- Подключение VS Code к Cage, удалённое размещение расширения и работа чата пока не проверены.

## Что возьму на себя и где нужен пользователь

Агент выполняет установку расширения Remote SSH, настройку соединения, проверку файлов, размещения расширения, IP и тестового чата. Пользователь вводит свои учётные данные и проходит подтверждение входа, если Claude этого потребует. Решение о доступе к новой папке или переносе проекта также остаётся за пользователем.

## Технические границы и проверка

- Системный VPN Windows и общий сетевой маршрут компьютера не меняются.
- Настройки прокси Cage и работа микрофона сохраняются.
- Используется отдельное подключение; существующие SSH-записи не перезаписываются. Перед изменением пользовательского SSH-файла сохранить локальную резервную копию.
- Не публиковать порты SSH в LAN/интернет и не отключать проверку ключа сервера ради подключения.
- Не копировать локальные Claude-токены, cookies или закрытые ключи между Windows и Linux ради авторизации.
- Конкретные SSH-параметры и пути выясняются из установленного Cage; `server-entry` для управления удалённым Cage не считать автоматически входом в Linux guest.
- Локальные подключения/резервные копии/секреты остаются вне Git. В репозиторий добавляются инструкция и обезличенные результаты.
- Если понадобятся вспомогательные скрипты, сначала написать проверку их поведения. Для ручной настройки обязательны реальные проверки подключения, удалённого процесса, IP, чата, файлов и повторного открытия.
- Откат: убрать только добавленную SSH-запись/новый ярлык, закрыть удалённое окно; вернуть резервную копию лишь если она не перезапишет более поздние изменения пользователя.

## На что обратить внимание при исполнении

1. Расширение случайно осталось локальным: проверить фактический extension host и процесс до авторизации/тестового запроса.
2. Ограничения ключа SSH мешают Remote SSH при разрешающем sshd_config: проверить реальный вход и туннель, а не только конфигурацию сервера.
3. Cage остановлен или сменил локальный порт: проверить новое подключение после повторного открытия среды.
4. Неожиданно открылась копия проекта: сопоставить папку и тестовое изменение с нужным проектом.
5. Вход Claude открывает браузер Windows: проверить штатный поток авторизации; не вводить учётные данные автоматически и не считать IP браузера Windows IP среды Cage.
