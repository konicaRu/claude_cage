# Ручное управление микрофоном Cage

> Изменение требования после реализации: пользователь попросил полностью автоматическое подключение при запуске Cage. Теперь действует `--watch` и пользовательский Startup-ярлык, корневые ручные CMD удалены. Ниже сохранён исходный план ручного этапа. Актуальная инструкция: microphone-bridge.md.

Автоматический этап завершён: 14 тестов, проверка установки Startup-ярлыка, обнаружения уже открытого Cage, preflight Realtek, автоматического старта и 3 секунд реального аудио. При недоступном устройстве проверка не меняет аудиослужбу; повторная попытка через 30 секунд. Независимое ревью указало риск частых перезапусков, он устранён preflight и backoff. Полный выход Cage и новый вход Windows не выполнялись для сохранения текущей сессии.

Пользователь подтвердил работу диктовки с Realtek после перезапуска Claude и попросил удобное включение/выключение. Реализуем в текущем проекте без автозагрузки и без изменения установки Cage.

Выбор: два запускаемых двойным щелчком CMD-файла и небольшое окно Python/Tk со статусом. Альтернативы: консольный прототип неудобен; системная автозагрузка выходит за согласованный объём. Используются уже установленные Python, FFmpeg и Cage.

Поток: Realtek → FFmpeg → stdin cage run → временный PulseAudio pipe-source. Дополнительный parec поддерживает поток при простое Claude. Исходная конфигурация /etc сохраняется. Изменения guest находятся только в /run. Состояние и журналы Windows — в .local/microphone/.

Запуск единственный (Windows file lock). Окно показывает постоянный захват микрофона. Stop или закрытие окна завершает дочерние процессы и восстанавливает исходный PulseAudio. Windows Job Object завершает дочерние процессы при аварии контроллера. Lease обновляется каждые 20 секунд; guest watchdog восстанавливает звук при отсутствии обновлений более 90 секунд. Никаких новых сетевых портов и автозагрузки.

Проверка: модульные тесты остановки/сбоя процессов и владения runtime; реальный старт, три секунды сигнала без сохранения записи, остановка и исходный источник, повторный старт. Пользователь уже проверил саму диктовку на прототипе; изменения управления требуют повторной проверки при использовании.
