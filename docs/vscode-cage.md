# VS Code → Linux Cage

## Текущий результат

Отдельное окно VS Code подключается к Linux Cage, графическая панель Claude Code открывается. Пользователь подтвердил это скриншотами с `SSH: Cage` и экраном входа Claude. Ссылка авторизации открыта пользователем в браузере Cage. Сервис сообщил, что текущему аккаунту нужна подходящая подписка для Claude Code; пользователь сообщил, что прежний аккаунт заблокирован. Работа приостановлена по договорённости до решения вопроса с доступным аккаунтом/подпиской. Успешный вход, запрос к модели и редактирование через Claude не проверены.

### Как снова открыть окно

1. Запустить Cage и дождаться готовности Linux.
2. В VS Code нажать `Ctrl+Shift+P`.
3. Выбрать `Remote-SSH: Connect to Host…`, затем `Cage`.
4. Проверить надпись `SSH: Cage` внизу слева; открыть панель Claude Code через её кнопку в строке состояния.

Текущая SSH-запись содержит порт VM 56834. После перезапуска Cage порт может измениться; автоматическое обновление ещё не настроено. Рабочий проект не переносился; сейчас удалённое окно открыто на домашней папке `/home/cage`.

## Проверка подключения — 2026-11-16

Первый этап пройден: подтверждён реальный SSH-вход из Windows и рабочий TCP-туннель в Linux guest.

- Cage: ready=true, vm_running=true, environment_update_required=false.
- Штатный SSH-конфиг найден в каталоге текущей Lima VM. Он генерируется Cage; не редактировался.
- Текущий адрес: `127.0.0.1:56834`, пользователь `cage`. Порт может поменяться после перезапуска VM, перед настройкой подключения перепроверить.
- Команды через Windows OpenSSH вернули `cage`, `Linux`, `/home/cage`, установленный Claude Code `2.1.322`.
- Публичный ключ сервера получен через работающий канал Cage; проверка Windows SSH выполнена с `StrictHostKeyChecking=yes` и отдельным known_hosts в исключённой из Git `.local/`. Закрытый ключ не читался и не копировался; использовалась штатная ссылка IdentityFile.
- Создан временный SSH local-forward, привязанный только к `127.0.0.1`; через него получен SSH banner guest. После проверки процесс и туннель закрыты.
- Пользовательские SSH-настройки, Cage, прокси и VS Code не изменены; расширения не устанавливались.

Это проверка основы подключения, а не завершённая настройка Remote SSH или доказательство маршрута расширения Claude. Следующий этап: добавить Microsoft Remote SSH и отдельное подключение Cage, затем открыть удалённое окно VS Code.

## Remote SSH установлен — 2026-11-16

Установлен Microsoft Remote SSH 0.128.0 с зависимостями Remote Explorer и Remote SSH Edit. Создан SSH alias `Cage`; стандартный пользовательский `.ssh/config` включает отдельный `.ssh/cage.config`. Используется штатный ключ Lima через IdentityFile, `StrictHostKeyChecking=yes`, `HostKeyAlias=cage-linux` и отдельный `.ssh/cage_known_hosts`. Повторный `ssh Cage` успешно вернул пользователя cage, Linux и /home/cage.

Первоначальный Include в `.local` проекта OpenSSH отклонил из-за наследуемых общих ACL проекта. Действующий конфиг и публичный known_hosts перенесены в уже защищённую пользовательскую `.ssh`; права проекта не менялись. Закрытые ключи не читались и не копировались.

Запрошено новое окно `code --new-window --remote ssh-remote+Cage /home/cage`. Журнал показывает запуск SSH Resolver и ожидание после `Install and start server if needed`, при `remote.SSH.remotePlatform={}`. На момент проверки каталога `/home/cage/.vscode-server` ещё нет. Пользователю задан вопрос о возможном выборе платформы и предложено выбрать Linux. UI проверить автоматически нельзя: Computer Use native pipe недоступен. Не считать удалённое окно, VS Code Server и Claude extension настроенными до подтверждения соединения.

Alias пока содержит текущий порт VM 56834; автоматического обновления порта при перезапуске среды ещё нет.

## Linux выбран, VS Code Server и расширение установлены

Пользователь выбрал Linux в окне Remote SSH. Журнал подтвердил успешную загрузку и запуск VS Code Server 1.146.0 (commit 69047191fc427f2f92828279aae1d90d8eeda7ab), Linux/Debian x86_64, SSH tunnel и созданный exec server для ssh-remote+Cage. Сервер слушает только loopback guest; с Windows используется SSH-туннель.

Windows CLI `code --remote ... --install-extension` сообщил о локально установленном расширении и не установил его в guest. Это обнаружено проверкой каталога расширений Linux. После этого официальное Claude Code 2.1.325 установлено через `server/bin/code-server --install-extension` внутри Linux; package.json найден в `/home/cage/.vscode-server/extensions/anthropic.claude-code-…/`.

Запрос внешнего IP из Linux через `ssh Cage` совпал с ожидаемым IP Cage (сравнение в памяти, адрес не записан). Это подтверждает сеть гостя, но не отдельный запрос из активированной графической панели. `claude auth status` в Linux вернул loggedIn=false, authMethod=none. Пользователю необходимо открыть панель Claude в окне SSH:Cage и выполнить личную авторизацию. Фактическая активация расширения в удалённом extension host, маршрут потока авторизации и тест чата пока не подтверждены. Секреты Windows не переносились.
