Проверено инструментами:
- `ssh Cage` не подключался: в `~/.ssh/cage.config` стоял порт 56834, а Lima `ssh.config` содержал 58378. После переопределения порта SSH остановился с `REMOTE HOST IDENTIFICATION HAS CHANGED`: закреплённый ключ в `~/.ssh/cage_known_hosts` не совпал с ключом гостя.
- Текущий ключ гостя получен через штатный канал Lima (`ssh -F` по `ssh.config`, `/etc/ssh/ssh_host_ed25519_key.pub`), отпечаток начинается `SHA256:+tLZ0KTq`. Порт и закреплённый ключ обновлены; перед правкой сохранены копии `cage.config.bak-<время>` и `cage_known_hosts.bak-<время>` в `~/.ssh`. `StrictHostKeyChecking yes` сохранён.
- После правки `ssh Cage` вернул пользователя cage, Linux, /home/cage. Внешний адрес из гостя заканчивался на .27, как в журнале US ISP; явное сравнение с IP браузера Cage не делалось. Расширение anthropic.claude-code-2.1.325 установлено в `~/.vscode-server`. `claude auth status` в госте: loggedIn=false.
- Создан `scripts/sync-cage-ssh.ps1` (один проход или `-Watch`, журнал `.local/ssh-sync.log`, один экземпляр через mutex). Проверен на временных копиях с неверными портом и ключом: оба значения исправлены, повторный запуск ничего не менял, режим `-Watch` вернул порт. Рабочие файлы при проверке не перезаписывались; временная папка удалена.
- Создан `scripts/install-ssh-sync-auto.ps1`. Первый запуск заблокировала проверка прав (Unauthorized Persistence). После разрешения пользователя он выполнен: ярлык `Cage SSH Sync.lnk` создан в Startup (powershell -WindowStyle Hidden -File sync-cage-ssh.ps1 -Watch), наблюдатель запущен (PID 29412, запись «Watcher started» в 11:37:18).

Обновлены README.md и docs/vscode-cage.md (новый раздел «Синхронизация порта и ключа», убраны фразы об отсутствии автообновления).

Не проверено: срабатывание наблюдателя после запуска VM с изменившимися портом или ключом; запуск ярлыка при следующем входе в Windows; вход в Claude в VS Code (нужен аккаунт с подпиской, прежний заблокирован); работа Claude Desktop/Code через US-узел, отказ прокси и cold start.
